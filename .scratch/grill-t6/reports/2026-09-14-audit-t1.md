## 4. BLOCKING finding — public-tier / CI test kill

**F-1 (blocking): `test/adr-0064-t1-wiring.test.js` T-2 calls `checkClasses(ROOT)` with no tier guard.**

- Evidence chain: `check-corpus-classes.js:77,92` wraps `requireCorpus()` in try/catch, but `src/shared/paths.js:70` does `console.error` + `process.exit(1)` — the catch is dead code. On any host without `private/bench-corpus` (public clone, npm consumer, CI test job), three tests in the new suite (lines 102, 124, 134) exit the jest worker mid-test instead of skipping with a reason.
- Demonstrated: preload hiding `private/bench-corpus` from `fs.existsSync` -> jest reports "process.exit called with '1'" at `test/adr-0064-t1-wiring.test.js:102` -> suite fails.
- CI impact: `ci.yml` test job pins `JIAHAO_TEST_TIER: public` and deliberately never references the bench-corpus secret; `run-test-gate.js --expected-suites 56` spawns jest -> this suite fails -> `test` job red -> converged `needs:[gate-all,test]` red. The commit as-pushed would break the required check.
- Standard breached: ADR-0056 D-A tier resolution + ADR-0057 D-A reason-carrying skips — every other corpus-bound suite (adr-0030/0031/0036/0037...) uses `resolveCorpus`+`corpusT`/`fullT`+`skipTest`; the round's own hard rule was "Public-tier tests skip only through test/helpers/skip.js". The new file uses `skipTest` for the python lane but not the corpus lane.
- Note the dead `o.skipFs` param in check-corpus-classes.js — an unused escape hatch that no caller passes (speculative generality; it would also have been the wrong fix — real-tree corpus verification on maintainer hosts is the point of the test).
