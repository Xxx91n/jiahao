## 2) 工业界心智模型（重点调研板块）

**a. 验证对象=合并结果，非被审对象（merge queue 语义）**。GitHub 官方文档明确：merge queue 建 `gh-readonly-queue/*` 临时分支，required checks 跑在**目标分支最新态+队列前序变更的合成结果**上（docs.github.com Managing a merge queue，已读全文）。PR head 上的绿是**必要非充分**。2026-04-23 GitHub 自家 merge queue squash 事故（devactivity 复盘 + Discussion #193645，已读）：230 仓/2092 PR 的 HEAD 与“已合并 PR 内容”失配，且**未被自动化监控捕获**，靠客服工单 3.5 小时后发现——教训原文即“正确性监控”缺位。这正是本轮元类的工业镜像：declare 时点验证的对象与 landing 后公开对象是两个 commit，且该缝隙是事故高发区。

**b. 公开对象的等价性验证要有可机械核对的绑定（SLSA）**。SLSA 验证规范（slsa.dev，已读）：验证的第一步是 `subject` 摘要必须匹配**在手的 artifact**，而非宣称的来源；expectations 与 provenance 分属两个绑定面。映射到本仓：**ADR 文档里 pin 的 lane sha 就是“声明”，公开历史才是“subject”**——R-B/R-C（引用公开历史不存在的 sha）在 SLSA 语义下就是验证直接 FAIL 的形状，不是“陈述瑕疵”。

**c. 可复现构建的定义（reproducible-builds.org，已读）**：“可复现性**由逐位比对验证**”——验证永远落在公开可得的 artifact 字节上，作者环境里的绿不进入定义。AVP 论文（arXiv 2608.18180，已读）进一步给出实证：分散构建生态中验证失败的主因是**元数据恢复缺口**（来源 revision 不可恢复居首）——R-B 的孤立 lane sha 正是“验证者无法从公开侧恢复被引用对象”的实例。

**d. 历史重写制造孤立对象是已知批评类**。keturn《What's Lost in the Squash》(2021，已读)与 jjmtaylor 的 squash 批评文（已读）记录了同一现象：squash/rebase 后原 commit 变成 "does not belong to any branch" 的孤儿，git 考古断裂；git-spice 把 stacked 分支被 squash restack 列为成文限制。R-B 的 `gb-local/*` restack 孤儿是该批评类在 GitButler 工作流下的具体化——工业界对策不是“禁止重写”，而是**重写后必须重锚引用**（restack ritual），这正是 α′ lane-sha 引文卫生腿的对应物。

**e. 落地边界后验证义务的成熟形态**：trunk-based doctrine（比较角度检索命中）把 CI 分为 pre-merge 强制 / **post-merge build-publish-verify** / runtime smoke 三层，明确“merge 时绿”与“落地对象绿”是两层义务；SLSA 把验证架构列为 upload-time / consumer / **continuous monitor** 三选一并 SHOULD 至少择一。即：工业界不假设“声明时验证过”覆盖“落地后”，落地边界后的再验证是**独立义务**——α′ 的 post-land 验证义务条款与之同构。

## 3) 推荐与理由

**推荐 α′（公开树等价契约轮），带下述加宽**；β/γ 否决。

- **否 β**：defer-0078 是 R-6/LOOP-2 N-3 的 skip 归因测量协议，与四根因**不同变更类**——把它与公开树红修复捆进一轮反而违反 D-001 同质性测试的正用；而“红束走轮外 hotfix”意味着文档引文卫生、末次变更电池覆盖继续无机制守门（E-25 类已两发），且 defer-0076 review 钟悬顶。
- **否 γ**：ADR-0078 kind:fix 让 γ 程序上可行，但四根因暴露的是**契约缺口**（验证对象/公开对象无等价断言），纯修复只清 instances 不清类；t34 D-002(v)“遮蔽类消灭”的承诺会被 R-D 的 8 腿 UNVERIFIABLE 直接打脸——gate 不可验证与 gate 红同为绿承诺失效。

**α′ 偏差/加宽建议**（对候选方案的修正，按优先序）：

1. **R-D 应按 defer-0070 先例注册为供给面事件，而非仅轮内修复**。corpus tarball 缺 mr-probes.jsonl 是 CI **外部**供给漂移——轮内只能修 manifest/补文件，复发须有 unfreeze-able 登记（owner + review date），否则违反“已注册项禁静默丢弃”的对偶面：未注册的复发源禁静默留存。
2. **lane-sha 引文卫生腿应优先复用既有 `rewrite-map-published` / orphan-ancestry 形状**（ADR-0084 D-A.4 `--published-only` 已有“引文覆盖+公开侧祖先”断言；ADR-0085 机制化注记已有 pinned-sha ancestry 腿）。加宽方向是**扩枚举面**（从 map 面扩到全部 doc 引文），不是新立机制——避免再造一个权威类。
3. **post-land 验证义务条款应绑定 SEAL 语义而非另设时点**：落地尾（ADR-0084 D-C/ADR-0085 D-E）本就要求终末波+封印；post-land 义务的自然落点是“封印后对 origin/main tip 跑一次公开侧等价核对，结果作为下一轮的入口事实”——避免与 ADR-0085 的时点语义打架。
4. **元类应升 CONTEXT.md 词条**（如 Public-Object Equivalence / 被验证对象≠公开对象），并按 t34-D-005(iii) 惯例在 spec 落地时定夺——不升账，属术语面。
5. **R-A 的 0x08 腐蚀文档**走 F-D 类事实修正通道即可，但须按 ADR-0078 披露“该文件从未跑过电池”这一事实于轮报告——首次披露通道规则（ADR-0084 D-F）适用。

**残余风险**：
- 公开树等价腿的**自指税**：断言“公开 tip 绿”的腿自身也在公开 tip 上——GitHub 事故证明正确性监控自身会失明，需要轮外第二方审计（defer-0030 通道）兜底，不能闭环于自证。
- lane-sha 卫生腿若枚举过宽会产生**误报噪声**（孤立但有意保留的引用，如 ADR-0085 t25 `drift` 保留实例、orphan-cites.json 留档）——需要白名单/分类豁免面，否则重蹈 alert-fatigue（defer-0004 已登记该反模式）。
- post-land 义务与单人维护者的**人手依赖**：ADR-0084 D-E 已声明 tag 依赖人类可用性；post-land 核对若也绑人类步骤，红窗将复现 defer-0025 式 pending——应尽量机械化为 CI 腿。
