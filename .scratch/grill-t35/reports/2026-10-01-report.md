## R-A - escape-eaten characters in a committed claim artifact [D-002, D-008#2]

Reproduction:

```
node -e "const B=require('fs').readFileSync('.scratch/grill-t34/handoffs/2026-09-30-reaudit-handoff.md');" \
  "const h=[];for(let i=0;i<B.length;i++)if(B[i]===8||B[i]===9)h.push('0x'+B[i].toString(16)+'@'+i);console.log(h)"
```

Output: `[ '0x8@1424', '0x09@1597' ]` - **two** control bytes, not one.

Pre-images, established from byte arithmetic rather than guesswork:

- `0x08` followed by `ut land --yes` -> `$but land --yes`
- `0x09` followed by `rend-inventory.json` -> `$trend-inventory.json`

Both are escape-eaten `$` characters (`$b` -> `\b`, `$t` -> `\t`) produced by a
shell layer, not by the author. Repo-wide scan of tracked text found this file is
the ONLY carrier of either byte.

Repair (forward-only; history is not rewritten): the file is rewritten with correct
text plus a disclosure section naming commit `71f3d4df` (grill-t34 audit PASS) in
display-form as the forensic record of the corrupted bytes.

**Finding beyond the task book.** The task book recorded one eaten character. There
were two, in one file, and the second is the more instructive one: the t18 doc-hygiene
signature set exempted TAB outright, so `0x08` was caught by the battery while
`0x09` passed through it undetected in the same file. The signature set now includes
a TAB that is not at the start of its line.

False-positive measurement for that new predicate, over the tracked text corpus at
registration: **exactly one hit, and it is this file**. The added strength costs no
false positives while closing the hole that let the second corruption land.

## R-B - lane-sha orphan pin [D-006]

Reproduction:

```
git cat-file -t origin/main:613a2471     # -> ERR (unrepresentable)
git merge-base --is-ancestor 613a2471 origin/main   # -> exit 1
git merge-base --is-ancestor 816e7bf3 origin/main   # -> exit 0
git log -1 --format=%H origin/main -- README.md      # -> 816e7bf3...
```

The mirror pinned `613a2471`, a lane sha that the landing rewrite destroyed.

Repair: the baseline is downgraded to a **display-form provenance record** and
re-pinned to the public README tip `816e7bf3` (verified an ancestor of
`origin/main`, so the recorded provenance is truthful). The three assertions that
made the pin an assertion target - exists-in-history, is-an-ancestor, equals
`git log -1 README.md` - are withdrawn as restack-fragile. The same-commit
obligation is retained and mechanized as a zero-sha historical pairing scan.

**Specification-reality gap, disclosed rather than silently absorbed.** D-006 as
written asks the scan to assert that every published-line README-touching commit
also touches the mirror. Measured on the real line:

| range | README-touching | paired | unpaired |
|---|---|---|---|
| whole published line (778 commits) | 151 | 16 | **135** |
| from the ADR-0079 anchor `982b52ec` (403 commits) | 28 | 16 | **12** |

(The first version of this report wrote "151 of 151 fail"; that was wrong twice
over - the count is 135, and 16 commits DO pair. The 135 figure also explains
itself: the zh-CN mirror was created at `533e97b8`, so the **376 commits before
it existed could not possibly pair** - the rule is retroactively impossible there,
not merely violated. The forward-only anchor exists for exactly that reason.)

The cause of the remaining 12 is that the two-step rhythm D6 itself describes
(README commit, then a separate re-pin commit touching the mirror) means
same-commit pairing was never a historical fact in the anchored range either.

Rather than weaken the assertion into permanent green, the historical backlog is
carried by a **committed, monotonically-shrinking ratchet baseline** - the shape
industry lint tooling converges on, confirmed by the t35 research pass
(Notion ratcheting, Android lint baseline, mypy-baseline, suppress-ratchet). Every
entry is re-derived by machine on each run, so no prose waiver channel exists. Three
reconciliations are enforced: unsuppressed violation fails, stale row fails, anchor
mismatch fails.

**The negative requirement is regression-locked.** The scan is deliberately NOT
remediation-aware. Measured: all 12 registered violations ARE followed by a later
commit touching both files, so a remediation-aware rule would have reported zero
violations and silently washed the entire backlog - which is precisely the
three-step laundering D-006 forbids. `test/adr-0079-wiring.test.js` asserts this
property so a future 'improvement' cannot reopen the hole.

## R-C - map coverage, and why the old invariant could not hold [D-005]

Reproduction of the four broken commits:

```
node -e "const rm=require('./scripts/build-rewrite-map');" \
  "...scanDocTokensAt(root,sha) vs the map in that sha's tree..."
```

| commit | citations | map rows | uncovered |
|---|---|---|---|
| 71f3d4df | 3813 | 3789 | 24 |
| a0008b3f | 3774 | 3758 | 16 |
| c0195aaf | 3758 | 3748 | 10 |
| 6d57f16d | 3757 | 3748 | 9 |

True root, recorded because a root is not a symptom: the per-commit embedded-map
invariant is **structurally unsatisfiable** under the GitButler multi-lane landing
model. A lane-era commit's embedded map was correct for its own lane tree; when the
docs branch linearized, that same commit's tree grew a documentation surface, so the
embedded map froze while the tree grew underneath it. Per-commit self-consistency
cannot hold once a lane commit is rebased onto a tree that did not exist when it was
written. Regeneration does not fix this class; only moving the invariant does.

Repair: **tip-map coverage is promoted to the blocking authority** - the map at the
published tip must cover the citation set of every claim commit on that line, as a
union. A live registry at the front of the line is restack-immune by construction.
The four commits self-heal through the tip map with **zero exemption entries** and
are not amended. The per-commit check survives whole as an audit-time advisory,
enumerated in `docs/governance/audit-checklist.json` so the auditor attests it.

**Two union-key subtleties, both forced by measurement and both shipped as tests:**

1. The union key is `file + sha`, not `file + line + sha`. Keying by line demanded
   a row per line-position ever occupied and produced **185 false reds where 2 real
   ones existed** - the same citation sits at line 58 in one commit's tree and line
   45 in another's because prose was inserted above it. Per-tree row correctness
   stays with `build-rewrite-map.js --check`, which keeps the strict discipline inside
   the tree it describes.
2. sha identity is prefix-aware. grill-t33 wrote a 7-char form where the tip map
   holds the 8-char form of the same object; string equality called an
   already-registered citation uncovered. This is the prefix rule
   `evidence-freshness.js` already applies to pins, used here for the same reason.

**Why the defect was invisible rather than merely unfixed.** The per-commit leg
spawned one full-tree grep per claim commit and re-read a ~4 MB map per commit.
Measured: ~12 s per commit, so roughly five minutes end to end. Under the CI timeout
the gate reported **UNVERIFIABLE**, and an unverifiable gate is not a green one - the
leg was neither passing nor failing, so the defect could not surface. A new batched
multi-tree scan (`scanDocTokensAtMany`, chunked at 8 trees with a 1 GB buffer ceiling)
answers the same coverage question in ~50 s. Row-identity against the single-ref form
is regression-locked by a parity test over five refs including all four R-C commits.

## D-004 / D-007 - post-land re-verification and the two-segment block

`scripts/check-post-land.js` fetches the public branch, materializes its tip in a
throwaway worktree, and runs a wave-bounded subset against THAT tree: tip-map
coverage, doc-hygiene, strict-pin resolution, and the pairing scan.

`scripts/check-post-land-sentinel.js` is the assertion leg, registered at gates
order 231. It asserts the block is present, that BOTH segments are present, and that
`pre_land.ran_at` is not earlier than the committer-date of the wave's last
claim-surface mutation.

Anti-masking is mechanical, not editorial: `judgeSegment` evaluates each segment
alone and the leg concatenates the verdicts, so a green segment cannot cancel a red
one. Regression-locked by four tests including the mixed-direction cases.

## Disclosures carried by ADR-0092 (stated, not buried)

- The `ran_at` timestamp is **self-filled: forensic, not preventive**. It catches
  forgetfulness and cannot catch forgery, because writer and committer share a trust
  domain. The forgery authority is `git show`-level replay.
- **No TSA is introduced** and an armed trigger is pre-registered: a demonstrated
  forgery case against a self-declared block promotes this to an independent trust
  domain. That promotion is a registered future decision, not an open question.
- The pre-land window is **narrowed, not closed**: mutation-to-run is minutes, not
  zero. The ADR does not assert "the tree did not change after the run".
- The sentinel **subordinates to and never replaces** the second-party audit channel
  (defer-0030); its audit scope is narrowed to the advisory block plus spot checks.
- `check-post-land.js` is **not** a CI leg: CI observes a tree only after it is
  public, which is the wrong observation point for a pre-public check.

## Pack-cap breach - CORRECTED MEASUREMENTS (audit M-2)

The first version of this section carried three wrong numbers. Corrected here with
measurements a reviewer can reproduce:

```
npm pack --dry-run --json                    # -> "size": 474291, 169 entries
node scripts/check-pack-smoke.js             # -> 474291 bytes, 169 files (agrees)
git worktree add --detach <tmp> 78d8a14c && npm pack --dry-run --json
                                             # -> "size": 451664, 164 entries  (pre-round)
node -e "console.log(require('./scripts/check-pack-smoke').packCapBytes())"   # -> 470000
```

| quantity | first version (wrong) | audited | **measured** |
|---|---|---|---|
| pre-round size | 432,782 | 451,664 | **451,664** |
| current size | 471,521 | 472,857 | **474,291** |
| over cap by | 1,521 | 2,857 | **4,291** |
| derived cap `ceil10k(M x 1.10)` | 530,000 | - | **530,000** from M=474,291 |

How the first version went wrong, recorded because the failure mode is the point:
the pre-round figure was **derived by subtraction** (current size minus the byte
count of the files I had added) rather than measured. Packed size is a function of
compression across the whole tarball, so the difference between the two packed
totals is not the sum of the added files' sizes. The subtraction produced a number
18,882 bytes too low, and the derived cap inherited the error - `ceil10k(471,521 x
1.10)` is 520,000, so the reported 530,000 did not follow from the reported input
even arithmetically.

The current figure is 474,291 rather than the auditor's 472,857 because this
rework wave added content after the audit (E-28, the widened enumeration, the
shared-scanner require). Both are snapshots; the measured one is authoritative and
is the number the owner should decide on.

**The cap amendment remains an owner act and is NOT minted here.** The mechanically
derivable candidate is `ceil_to_10_000(474,291 x 1.10)` = **530,000** bytes.
ADR-0039 D4 states that bumping a cap is only ever an ADR, and the trend-anchor
protocol lives in ADR-0062 D-B. This report states the measurement and the
derivation; it does not apply them.

| item | value |
|---|---|
| measured packed size | 474,291 bytes (169 entries) |
| measured pre-round size | 451,664 bytes (164 entries) |
| current registered cap | 470,000 bytes |
| over cap by | 4,291 bytes |
| trend-derived candidate | 530,000 bytes |
| disposition | **owner-action: cap amendment ADR required** |

Consequence: the pack-cap leg (`adr-0038-wiring` D1, `pack-smoke`) is red for this
reason and is reported red. It is not counted as met, and no 'packaging passes'

## Rework wave - defects the rework wave introduced

Recorded on the same principle as the section above: the rework fixed real defects
and introduced new ones. The difference is that these were caught by RUNNING the
thing rather than by reading it.

- **`--root` was added to two scripts and wired into the parent.** The first wiring
  attempt passed `--root` to `check-orphan-ancestry.js` while that script still
  resolved ROOT from `__dirname`; it was silently a no-op until the script itself
  gained the flag. A flag that exists in the caller but not the callee is the same
  class of lie as B-1, one level down.
- **`DOC_PATH_RE` was widened and its declaration destroyed.** A split/join over a
  string that also appeared inside the replacement text truncated the const line,
  leaving `DOC_PATH_RE is not defined` at runtime while `node --check` stayed green
  (the identifier resolves only when the function runs). The map generator failed
  loudly on the next run; nothing was committed in between.
- **The pairing count was overstated twice** (151 of 151, then 135 without the 16
  that do pair). The 376-commit fact - the mirror did not exist for most of history
  - was available the whole time and is now in the report, because it explains why
  the forward-only anchor is not an evasion.

**Common thread:** every one was a claim about state that a command would have
settled, made from inspection or inference instead. The audit process findings are
the same finding one level up. None of this is fixed by being careful; it is fixed
by running the command and reading its exit code, which is what the round's own
contract now enforces mechanically.
