## Lessons learned

1. GitButler commits do not refresh `.git/index`; `git status --porcelain`
   then reports committed files as staged deletions, and but's index also
   auto-stages never-commit candidates — evidence legs that read porcelain
   or `ls-files` must run after an index resync (`git reset`).
2. Escape-interpreting layers also eat `\uXXXX` ranges inside regexes —
   the C1-char check now uses codePoint arithmetic, no regex literal.
3. The coverage-base pin is per-round state: each round's closeout must
   re-anchor it to that round's base AND update the latest-row assertions
   to the new row (name-addressed pins for older rows).
4. Facts canon ordering: rewrite-map must regenerate after the final doc
   commit, before the final facts collect (same regen-fixpoint lesson as
   t21/t22) — and the collect/regen pair converges only when facts'
   battery_as_of is already inside the map's citation set.
5. but-commit id lists must be enumerated precisely — grep-matching a
   basename (`clean-tree.txt`) swept five never-commit audit captures into
   a commit; revert + restore preserved the convention without losing bytes.
