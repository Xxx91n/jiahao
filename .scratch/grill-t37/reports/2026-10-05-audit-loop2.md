### 3.2 N-2: `adr-0085` live-leg-state is a workspace-topology flake — new defect class, owner scope

Observed timeline on the settled tree:

| Instant | Result |
| --- | --- |
| Audit `run-test-gate` (07:40Z artifact) | FAIL — `pin 68c8ec2f not ancestor of HEAD` |
| Manual `orphanAncestry()` eval ~min later | green — `violations:[], trigger.state:ok, red:false` |
| `git merge-base --is-ancestor 68c8ec2f HEAD` / `… refs/heads/gitbutler/workspace` | ancestral / ancestral |
| Focused `jest -t "live leg state"` re-run | PASS (15.4s) |

Root cause (read from `evidence-freshness.js` §520–548): pin ancestry is
evaluated against **HEAD** — which on this repository is a GitButler
workspace merge commit that is rebuilt on every apply/restack. The violating
pin `68c8ec2f` (`grill-t29` evidence, `captured-at-head`) is not reachable
from the workspace merge *base*; it enters HEAD only through applied-lane
lineage. Whenever the applied-branch set changes (apply-branch churn visible
in `git reflog`: multiple workspace checkouts this session, including during
the audit's own test run), the pin transiently falls out of ancestry and the
test goes red. The same red appeared inside the rework lane's post-closeout
verification artifact.

This is the identical defect **shape** as the orphan-cites clock pin
(live-state test bound to a moving environmental variable — there: wall
clock; here: workspace merge topology), but the disposition is owner/spec
scope, not fixes scope: either (a) evaluate ancestry against a stable ref
(e.g. the carrying lane tip or merge-base rather than the transient merge
commit), (b) register an errata class for topology-transient windows, or
(c) accept the flake as a true "restack orphaned the pin" signal — which on
GitButler would fire on routine parallel-lane ops, costing the post-restack
ritual every time. The audit lane does not adjudicate which; it reports that
the current formulation makes the test nondeterministic in a shared
workspace.
