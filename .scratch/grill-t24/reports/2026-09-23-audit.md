## Process incidents (reported separately — not ratified)

- **I-1 — post-closeout evidence pollution by a bun-sandbox recapture.** During
  this audit window the worktree evidence dir was rewritten (mtimes 10:42 and
  11:04–11:05) by a capture run whose `process.execPath` was **bun.exe**:
  `gate-all.txt` ends in a Bun illegal-instruction panic, `run-test-gate.txt`
  shows 78/78 suites failing in 1.7 s, `liveness.txt` fails on a bun-relative
  `npm-cli.js` path. All 24 files now carry `captured-at-head: 28cb29a` with red
  bodies. **Uncommitted — the durable tree is intact and is what I audited.**
  Two lessons: (a) the capture harness is not runtime-portable — it silently
  inherits execPath; it must pin `node` or refuse non-node runtimes; (b) if any
  session commits these red bytes, the round's own D-A invariant is violated in
  spirit — the worktree must be discarded-to-committed or recaptured under node
  before any further commit lands.
- **I-2 — audit-side collision consequence.** With the polluted worktree,
  `build-rewrite-map.js --check` goes red (evidence headers are doc citations)
  → `rewrite-map.test.js` fails inside `jest --json --silent` →
  `build-round-facts.js --check` exits 2 ("verifier broken"). The committed
  `round-facts.txt` green is plausible only on a clean maintainer tree. This is
  the already-registered defer-0064 conflation surfacing — no new defect, but
  the chain demonstrates why evidence-dir hygiene matters.
- **I-3 — allowlist usage is not independently re-verifiable post-hoc.**
  GitButler's operations log carries no commit records; conformance was verified
  through the landed file lists themselves (the substantive receipt). The
  process claim "every `but commit` named an explicit allowlist" is consistent
  with the evidence but not provable from it.
