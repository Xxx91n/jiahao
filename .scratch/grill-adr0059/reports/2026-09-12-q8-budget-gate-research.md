# Q8 调研 — 预注册确认性门值在合法增长下变得不可达 (2026-09-12)

- 工具: atomcode-research（单问、不预列角度/域名；在 ctx_batch_execute 内运行；timeout 600000）
- 规模: 15+ 检索（Exa 4 / Tavily 4 / AnySearch 7）；9 篇原文核验 + 1 次 fetch_output 全文；五类角度全覆盖（Official / Comparative / Criticism / Currency / Community）
- 本地取证: 调研方自行 grep/读取 ADR-0039/0060/0058/0059、test/adr-0038-wiring.test.js、package.json、.scratch 实测链，并 1:1 复核了 M=140,778、205,741/92 files、−4,764 杠杆、CONTEXT.md=95,707 B、测试从 ADR 解析 cap 无魔数、以及已撤回的 1.25 公式误用

## 1) 执行摘要（原文要义）

**「没有不可修订的预注册值，只有不可静默修订的预注册值。」** 修订权属**规格所有者**（本项目 = ADR 决策主体/项目负责人），不是写测试的人，更不是被测对象本身。合法性五要素：
**触发**（cause-driven，非 failure-driven）、**程序**（正式渠道：新 ADR / ADR 修订）、**证据**（测量链 + 增长分解 + 不确定带重估）、**记录**（修订 + 双向指针 + 与门值同提交）、**时机**（前瞻性，非事后调值让现有数据通过）。

本案：200,000 按 ADR 自身规则（公式以收窄轮 M 为键）无法自动重算；排除偶然面后仍只有 92 字节余量、落入被拒绝的假警报带 → **门结构上不可达，再校准正当且必要**，但必须走正式 ADR 决议。Confidence：**高**（关键结论均有 ≥2 独立信源交叉验证）。

## 2) 分点结论（每条带来源）

**① 权责分离：规格限归规格所有者，测试无权移动限值（计量学）。**
ISO/IEC 17025:2017 §3.7 定义决策规则；ILAC G8:09/2019：决策规则「必须在测量开始前与客户商定并文档化」；JCGM 106:2012：「**选择公差限与接受限是业务或政策决策**」（经 CMM Quarterly 原文引文核验）。
→ 200,000 是规格限（business decision），门测试是执行预先商定决策规则的计量仪；测试因撞墙而改值 = 计量者篡改规格。

**② 确认性资格：修订可以，事后调值不行（ICH E9 §5.1 / FDA）。**
「只有方案中预见（**包括正式方案修订**）的分析才能被视为确认性的」；「SAP 无法追溯地创造确认性状态」；揭盲后重定义主终点「几乎总不可接受」。
→ 抬限本身合法，但必须是「新 ADR 修订 ADR-0039 D3」的正式决议，**而非把测试锚点悄悄改大**。

**③ 偏差不可避免，纪律在披露（开放科学预注册）。**
459 项预注册研究过半增删假设；23 篇论文中 21 篇偏离原计划、仅 1 篇完全披露（van den Akker 2023 / Claesen 2021）。解法不是禁偏差，而是**偏差披露表（类型/原因/时机/影响）**；编辑对「已披露」反应中性、对「未披露被抓包」反应负面。Simmons/Nelson/Simonsohn 2011 给出机理：未披露的灵活性使假阳性率膨胀。
→ 本案 ADR-0039 的 budget-status note 与 ADR-0060 的「Currently breached…NOT met」正是教科书级披露（已做对）。

**④ ADR 不可变，修订留痕（Nygard / ADR 社区规范）。**
Nygard：决策被推翻时**保留旧 ADR、标记 superseded**；社区规范（16.9k★）：「Immutable: Don't alter existing information in an ADR. Instead, amend… or supersede…」；supersession 模式（WhyChose 2026-05）：**双向指针 + 单次原子提交**；单向 supersession 是目录最常见的完整性 bug。

**⑤ 默认处置是停，例外是文档化的产品决策（Google SRE）。**
误差预算政策：预算耗尽 → **默认冻结所有变更与发布（P01/安全除外）**；政策文档须含作者、复核人、批准人、批准日期与**重审日期**；「放松 SLO」合法但须由可论证理由驱动，且须理解权衡。

**⑥ 预算再校准是常态：测量后 +25%（size-limit 官方 / Code With Seb）。**
size-limit 官方 README 原话：「Add 25% to the current total size and use that as the limit」——本项目 `max(200,000, M×1.25)` 正是业界标准启发；预算生命周期：测量 → 按当前值 +10–20% 设限 → CI 强制 → 季度收紧 → 「新功能带重依赖时可放松，**必须记录为什么**」。反例警示：「aspirational budgets that always fail get ignored」。

**⑦ 假警报疲劳与 Goodhart：紧门训练反射式抬限（Johnson 2013 / 医疗警报研究 / Calypso）。**
医疗监控 72–99% 警报为假 → 脱敏与 crying wolf；KPI 治理建议把被游戏化的指标当「坏掉的仪器」而非道德失败，配护栏 + 升级规则。ADR-0039 R4 拒绝紧预算的逻辑与此一致——**本案的 92 字节余量结局恰好实证了 R4 的担忧**。

**两源冲突说明**：唯一分歧在「抬限时机」——SRE 默认冻结直到恢复（保守），size-limit / Code With Seb 允许「合法增长 + 记录理由」下立即再校准（务实）。调研采用折中：**记录非符合 + 修复偶然面先行，再校准决议走正式 ADR 同步落地**。

## 3) 对比矩阵：修订预注册门值的行业路径

| 心智模型 | 谁有权修订 | 程序 | 证据要求 | 记录方式 | 防反射机制 |
| --- | --- | --- | --- | --- | --- |
| 计量学（ILAC G8 / JCGM 106 / ISO 14253-1） | 规格所有者（业务/政策决策） | 测量前商定决策规则；改限=规格变更 | 不确定度量化、风险（PFA/PFR）、与客户一致 | 决策规则与符合性声明文档化 | 守卫带预先算定（w=U→PFA<2.5%）；w=0 共享风险被拒 |
| 确认性统计（ICH E9 §5.1 / FDA） | 申办方+监管审查 | 正式方案修订（前瞻性） | 修订理由、对结果的效应检验 | 修订写入方案与报告，原值保留 | 事后改判自动降级为探索性（丧失确认资格） |
| 预注册开放科学 | 研究者+期刊审查 | 偏差披露表 | 偏差分类+透明披露 | 披露表随稿提交 | 未披露偏差遭负面审查；披露即豁免 |
| ADR 治理（Nygard / 社区） | ADR 决策主体 | 新 ADR supersede/amend + 双向指针 + 原子提交 | Context 变化说明 | 旧 ADR 置 Superseded/Amended，正文不改 | 不可变性；单向 supersession=完整性 bug |
| SRE 误差预算 | 具名 approver | 书面政策+例外决策；默认耗尽即停 | 预算耗尽归因 | 政策含作者/复核/批准人/重审日期 | 停止发布为默认；放松须理解权衡 |
| 包体积预算（size-limit） | 团队（CI 门强制） | 测量后 +25% 再校准；季度重审 | 当前实测+增长归因 | 预算文件+PR 记录+文档化理由 | 假警报疲劳→永远失败的预算被无视 |

## 4) 可落地推荐（按步骤，映射本仓库既有机制）

**步骤 1 —— 先修偶然面（零争议）**：排除自动收录的 `bench/polygraph/README.md`（−4,764 B）。这不是削减检查，而是修正「白名单意图 vs npm 子目录 README 自动包含规则」的打包不一致（wiring 测试已实证子目录 `.npmignore` 可覆盖）。修完 ~200,977 B **仍超限**；即便再排维护者门脚本也只剩 92 B 余量，**落在 R4 拒绝的假警报带内，不能作为通过态**。
  - **明确不做**：repo-tree 门脚本在 `scripts/` 白名单内，且只读 git tree（ADR-0038 D2/D3 已验证不碰消费者运行时）；「降级声明绝不降级检查」**禁止为过门删它**——除非另行独立 ADR。

**步骤 2 —— 走唯一合法的抬限通道：正式 ADR 决议（amends ADR-0039 D3）**。证据三件套：
  - (a) **测量链与程序不变性**：同一测量程序（`npm pack --dry-run --json` 的 size 字段），逐轮记录；
  - (b) **增长分解表**：新增运行时代码 / CONTEXT.md 95,707 B / repo-tree 门脚本 / 已修的 −4,764 B 偶然项，每项对照 grill Q4 裁决；
  - (c) **噪声底与不确定带重估**：92 B 余量证明原带已失真，目标余量回到 ~25% 头寸并声明落在不确定带之外。
  - **建议新值：255,000–257,000 区间**（=205,741×1.25≈257,176；与预注册公式同构，但经正式决议而非自动触发落地——既尊重公式精神，又不落入「撞墙即抬」的反射）。**时机必须前瞻**：决议先于/同轮生效，非事后补票。

**步骤 3 —— 权威与复核（复用双档案设计）**：提案由 generator 档案出，**verifier 档案作阻断性复核**，认证三点：抬限基于原因分解而非失败反射、测量程序未变（无检查被削减）、新余量在不确定带外。

**步骤 4 —— 记录**：新 ADR 头 `Amends: ADR-0039 D3`；ADR-0039 头加 `Amended by:` 双向指针；200,000 保留在原文（不可变历史）；wiring 测试锚点**自动跟随**（字面量锚定设计的回报）；deferred-registry 注记同步；README ADR 索引重建；**全部同一提交**（working agreement + ADR-0027）。

**步骤 5 —— 防反射机制加固**：(a) 抬限成本显性化——wiring 断言可拦截「无分解表+无噪声重估的抬限决议」；(b) 提前预警替代撞墙——观测「余量 <15%」作为预算审查 ADR 的触发（对标 SRE burn-rate 预警与季度重审）；(c) 解耦保持——可「带记录的非符合放行 + 决议在轨道上」，但绝不允许「为放行而静默改限」。

**备选/根治路径（开放问题）**：CONTEXT.md（95.7 kB）占打包面近半且仍在增长——即便抬到 257k 也可能再次不可达。根治：修订 ADR-0038 D1，把词汇资产从「运行时面硬上限」中单列（「留在打包面」≠「计入同一硬上限」；更早的 grill 裁决可被更晚的正式 ADR 修订）。
