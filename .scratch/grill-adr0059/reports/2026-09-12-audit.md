## 4. 双轴评审（$code-review：固定点 62046da，两轴不合并不重排）

### Standards 轴（仓库标准 + Fowler 基线异味）

**硬违反**
- S-H1 **CONTEXT.md 词汇表数值陈旧**：CONTEXT.md:1133 仍写「measured-anchor budget 200,000 bytes per ADR-0039」，而本轮已把 cap 重算为 253,999。CONTEXT.md 是 AGENTS.md 指定的领域真源，且本轮工作协议要求每轮同步词表。该字面量在本轮 cap 变更后成为陈旧事实，且被 §13「陈旧计数扫描」漏检。

**判断题**
- S-J1 **轮次 Standing rule「Pack budget hard cap 200,000 bytes」 vs 实测 205,741 B**：本轮以 ADR-0039 D3 预注册公式重算至 253,999 自辩。但 D3 定义 M 为「narrowed tarball 的实测值（预期 ~140-150 kB）」，本轮把已膨胀的当前尺寸 M=203,199 当锚，属自指式抬顶；ADR-0039 自身 R4 警告「tight caps train reflexive limit-bumping」。倾向违规，须人工定夺（见 §5 V-1）。
- S-J2 **触碰受保护路径**：Standing rule 列 bench/polygraph/results/* 为禁碰；55c95eb（kvo）新增 bench/polygraph/results/reverify-20260912.json。与 ADR-0030 D3「reverify-<date>.json 须提交」直接冲突——规则冲突本身需人工裁定（见 §5 V-3）。

**基线异味（均 judgement call，部分报告已显式处理）**
- Duplicated Code：src/instrument-identity.js 的 signoff / conditionalSignoff 守卫阶梯重复 —— 报告 §10 已「显式不予采纳」并给理由（谓词不同），审计认可该理由成立，仅记录。
- Duplicated Code：scripts/check-pack-smoke.js 的 tarball 表面集合 与 test/adr-0038-wiring.test.js 的同类断言，一个契约两处维护 —— 新增 judgement call。

### Spec 轴（决策台账 D-001..D-006 + 任务书 + ADR-0059/0060）

**(b) 未要求的改动（范围蔓延）**
- P-B1 **打包上限被单方面抬高**：任务书 Standing rule 与 ADR-0059 Acceptance 均写 < 200,000 bytes，实现改为 253,999，并连带改写 ADR-0059/0060 验收字面量。触发增长主要来自本变更集自身（CONTEXT.md 等）。

- P-C1 **自签认证**：instrument-state seq3 conditional_signoff 与 seq5 record_signoff 的 reviewer_id 均为 Euiop1，而 git user.name = Euiop1、提交者 = Euiop1 —— 即签署标识与执行代理同一身份。提交 2473402 自述「identity re-pin + human sign-off PENDING」，与 D-006 冲突。报告 §7.4 以「本会话两次人工授权」补记，但**仓库内无任何可验证的人工签署工件**。
