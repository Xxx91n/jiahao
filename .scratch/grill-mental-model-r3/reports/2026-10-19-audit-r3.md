## 2. blocker（打回原修复窗口返工一次）

### B-1 `duplicateTokenDefinitions` 漏检"两行同 canonical token"

- **位置**：`scripts/shared/coinage-triage.js:384`（函数体），缺陷判定在 `:393`；接线 `scripts/coinage-triage.js:90`
- **级别**：blocker（声明证伪 / T-3 验收"十三件全部落地"未达）
- **证据（确定性，rung1）**：
  ```text
  case A {rows:[{token:'foo'},{token:'foo'}]}                     → []
  case B {rows:[{token:'foo'},{token:'bar',synonyms:['foo']}]}    → [{token:'foo',firstRow:'foo',secondRow:'bar'}]
  case C {rows:[{token:'foo',synonyms:['baz']},{token:'bar',synonyms:['baz']}]} → [{token:'baz',...}]
  ```
  `owner` 以 `row.token` 为值存储，守卫 `owner.get(t) !== row.token` 本意是跳过"行内自指"，却同时吞掉了"两行同名 token"——此时 `owner.get(t) === row.token`，判定为假，不产生 finding。
- **与声明的差距**：报告 `T-3 #2` 声明为"同 token 双行 / 跨行冲突披露"；函数自述注释为 "Two rows sharing a token (or one token listed in another row's forbidden_synonyms)"。**第一子句（同 token 双行）实测不成立**。
- **附带**：`grep -rn duplicateTokenDefinitions test/` 无命中 → 该函数**零单测覆盖**。
- **修复要求**（最小且正确）：去重键改为**行身份**（行下标/行 id），而非 `row.token`；令"两行携带同一 token"被计入 duplicates。
- **修复后必须重跑（与 §0 同一套验收）**：
  1. `npm test`（新加：同 token 双行 / 跨行 synonym 两个方向的单测）
  2. `node scripts/coinage-triage.js` → rc=0
  3. `node scripts/build-adapters.js --check` → rc=0
  4. `node scripts/install.js --help` → rc=0
  5. `node bench/research/devin-oot.js --replay` → rc=0
  6. `node scripts/corrigendum-v3.js --check` → rc=0；`node scripts/check-pairer-regression.js` → rc=0

> 说明（供你拍板）：B-1 影响面**受限**——该函数是 advisory 面、未立新原则，当前 substitution_table 无重复 token，故无现实漏报。若你判定其仅需记 backlog，可降档；但按本任务"声明证伪=blocker"的二分规则，审计窗据实判为 blocker。
