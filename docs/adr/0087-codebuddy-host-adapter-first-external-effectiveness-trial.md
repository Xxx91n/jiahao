# ADR-0087: CodeBuddy Host Adapter — First Claude-Code-Compatible Path, Pending-Confirmation Tiering, and the First External-Effectiveness Trial Protocol (grill-t30)

- Status: Accepted — ID-level-only, awaiting entity-level countersign; return condition: the 2026-12-15 tide; return-by: 2026-12-15
- Date: 2026-09-27
- Ledger: `.scratch/grill-t30/decision-ledger.md` — grill-t30 D-001..D-005 (all current)
- Spec: `.scratch/grill-t30/spec-t30-codebuddy.md` (injection-surface ruling, bundle, protocol, leg, registrations)

## Context

CodeBuddy is the first host that reaches jiahao through the
Claude-Code-compatible plugin path: the official compatibility chapter
recognizes `.claude-plugin/` and `${CLAUDE_PLUGIN_ROOT}` verbatim
(`${CODEBUDDY_PLUGIN_ROOT}` takes precedence when set). The existing host
family under ADR-0028 D6 spans hook-tier (claude-code, codex, copilot,
qoder), instruction-tier (cursor, windsurf, cline, opencode, aider,
AGENTS.md) and the MCP stub — none of them is a *plugin-bundle* host. Two
new problems arrive with this one: (a) a distribution form that vendors
the runtime into a self-contained plugin dir, and (b) a host whose
CLI-vs-IDE surface parity is documented but not live-probed — the round
needs a tiering word between "verified" and "absent" that does not lie.

The same round carries the first external-effectiveness trial design
(SCED-shaped, single-case) and mechanizes the E-17 wave-closeout lesson
as a gate leg.

## Decision

### D-A — Admission + tiering extension (ledger D-001/D-002)

**CodeBuddy is admitted as host 12 via a new path family: the
Claude-Code-compatible plugin bundle.** This EXTENDS ADR-0028 D6's tier
table — it does not stand parallel to it:

- ADR-0028's enforcement tiers (hook / instruction / MCP) are unchanged.
  What this ADR adds is a *distribution-path* family inside the hook
  tier: a self-contained plugin bundle whose manifest dir keeps the
  `.claude-plugin/` name unchanged for single-source reach.
- A new verification tier precedent lands alongside it: surfaces are
  either **verified** (live-probed, evidence cited) or
  **declared-unverified** (documented but unprobed — registered as
  pending-confirmation exceptions under the ADR-0086 channel with
  `status`/`requested_by`/`reason`/`expires_at`/`scope`). An item that is
  declared-unverified is never claimed as working; ratify/revoke is an
  owner act at the next authority event (the 2026-12-15 tide).

### D-B — Bundle shape (ledger D-002)

`adapters/codebuddy/` is the plugin root, generated by
`scripts/build-adapters.js` (ADR-0028 D2 regen-diff golden layer covers
it like every other adapter):

- `.claude-plugin/plugin.json` — manifest lives only inside the manifest
  dir; `defaultEnabled: false` is the conservative default.
- `hooks/hooks.json` — the five migrated events (SessionStart,
  SubagentStart, UserPromptSubmit, Stop, SessionEnd) plus the
  `InstructionsLoaded` integrity assertion (records both rules files'
  presence + sha256 into a telemetry log) and `PreToolUse` wiring that
  emits `permissionDecision: "deny"` when a tool call targets the
  enforcement surface (injected rules, hook map, manifest, jiahao
  state/evidence) under the verifier profile.
- `rules/jiahao-{verifier,generator}.md` — dual profiles with
  `alwaysApply: true` frontmatter.
- `.mcp.json` + vendored `jiahao-mcp/` — the existing stdio server.
- Hook scripts and their static require() closure are vendored
  byte-verbatim under the bundle (the plugin root must resolve them
  standalone).
- Every assertion/enforcement line lives in `hooks/hooks.json` — plugin
  hooks bypass the `allowUntrustedFrontmatterHooks` gate and are
  effective on enable. Nothing load-bearing goes into frontmatter
  (silently skipped by default).

### D-C — Injection-surface ruling is the adapter README

The Verified / Declared-unverified ruling table lives in
`adapters/codebuddy/README.md` (per spec section 5) — a disclosure
surface governed by the ADR-0074 D-F push discipline (re-verification +
audit pass before push). Every declared-unverified row has a
pending-confirmation entry under
`docs/governance/surface-taxonomy.json`'s
`host_admission.hosts.codebuddy.declared_unverified` channel.

### D-D — Trial protocol + preregistered judgment lines

The external effectiveness protocol is SCED-shaped, multiphase A1-A2-A3
with isomorphic-but-not-identical task volumes, telemetry
self-verification as Phase 0 item 0, and cross-phase conditional
judgment lines preregistered before execution. The judgment-line file
lives on a persistent, referenceable, version-controlled surface —
`bench/codebuddy-trial/judgment-lines.json` — and every line carries
`source_adr: "0087"`. This ADR records the *decision to preregister* and
the invariants (immutable lines, errata channel for deviations, frozen
`detect()` reference, host-version changes as errata); it deliberately
copies no criterion values — values live in the registered file.

Legitimate output of the trial is hit/miss against preregistered lines
plus an effect-size impression — never effect numbers or p-values this
round, and the polygraph corpus is demoted to an appendix probe of the
deny apparatus, never cited as effectiveness evidence.

### D-E — Companion machinery (registered, not legislated here)

The E-17 wave-closeout leg (`map-freshness`, gates.json order 224) is
companion machinery of the same round, legislated by ledger D-004 with
its provenance in ERRATA E-17; this ADR names its registration only —
the leg's semantics are deliberately not restated here (ledger
D-005(vi): same round, different clause).

## Rejected alternatives (ledger Q2'/Q3'/Q5')

- **β compatibility-note-only** — a declaration is not an execution
  channel; it would forfeit the `InstructionsLoaded` audit anchor.
- **γ instruction-tier-first** — rules alone carry no blocking channel;
  the verifier iron laws would float unenforced.
- **δ MCP-only** — prompt delivery without lifecycle hooks; same
  enforcement hole.
- **α naive three-phase without parallel volumes** — learning effects
  become unresolvable; SCED's within-phase replication is the control.
- **judgment lines under `.scratch/`** — a round surface is not a
  registered surface; preregistration degrades to self-declaration.
- **no ADR (β')** — loses the rejected-option record and breaks the
  `source_adr` back-pointer chain.

## Consequences

- `test/fixtures/host-contracts.json` gains four codebuddy rows
  (verdict-gate, fail-soft fan-out incl. InstructionsLoaded/PreToolUse,
  config-event map, bundle files) + a `lifecycle.codebuddy` entry; the
  contract matrix and coupling rule now govern this host like the rest.
- `test/codebuddy-adapter.test.js` pins the bundle structure
  (manifest-dir-only manifest, components at root, vendored byte-parity,
  live InstructionsLoaded/PreToolUse behavior).
- The taxonomy gains a `host_admission` block whose
  `declared_unverified` field is an ADR-0086 exception channel — the
  first pending-confirmation registration outside the claim/errata
  families.
- `bench/codebuddy-trial/judgment-lines.json` is immutable after
  registration; trial deviations and host-version changes ride the
  errata channel, never edits.
- Wiring pin: `test/adr-0087-wiring.test.js`.

## Self-audit

New normative semantics introduced by this ADR: the
Claude-Code-compatible path family inside the hook tier; the
verified/declared-unverified tiering word bound to pending-confirmation
registration; the immutable preregistration-file convention with
`source_adr` back-pointers; errata-channel treatment of host-version
changes. The E-17 leg is companion machinery, not semantics of this ADR
(D-E). The trial's execution, all ratify/revoke calls, and this ADR's
countersign remain owner-side.
